## 背景与目标

### 问题

完整的企业级 SDLC 平台通常把「数字员工 + 小队 + 工单 + 派发」做成一整套组织级基础设施，依赖 Java / Spring Boot、MySQL、Redis、对象存储、本地执行器 daemon、WebSocket 长连接等组件，理解成本高、复现成本更高。

本项目的目标不是复刻功能，而是**提炼最小闭环**：一个任务从「选择场景」到「多个角色化 Agent 依次执行」再到「人能看到每一步发生了什么」，需要哪些最小概念与机制。

### 三个核心目标

1. **Agent 管理**：创建角色化 Agent，给它挂载 Skill（方法/操作指令）与知识（规范/业务/经验），并能预览最终注入模型的上下文。
2. **Workflow 管理**：把任务拆成若干步骤，每一步指定一个 Agent；步骤之间有显式依赖；可在步骤上设置人工审批卡点。
3. **任务管理**：输入任务描述后按场景匹配 Workflow，启动执行，实时观察每一步的状态、流式输出、耗时、Token 与事件；支持人工审批、取消、重跑。

### 非目标（明确不做）

- 多租户、登录、SSO、RBAC；
- Squad（小队）、跨团队数字人共享；
- Agent 版本评审 / 发布 / 回滚；
- 本地执行器 daemon、WebSocket 调度、任务包（远程沙箱为独立草案，见 [远程沙箱设计](11-sandbox.md)）；
- 记忆审核流、向量检索、RAG；
- DAG 拖拽画布、条件分支、并行执行（**数据模型与引擎已兼容，UI 暂不提供**）；
- 成本/配额看板、IM 通知、定时任务；
- Skill/知识文件上传与解析（以 Markdown 文本录入）。

> 本项目是**演示与设计验证系统**，默认只监听 `127.0.0.1`，没有鉴权，不应直接暴露到公网。

## 设计取舍

### 常见平台的关键概念

| 概念 | 含义 |
|---|---|
| Agent / 数字员工 | 角色化 AI worker，有身份、职责、技能、记忆、默认流程 |
| Skill | 可复用技能包，执行器据此加载 |
| Memory | 团队经验库，按 AGENT / SQUAD / ORG 作用域挂载，审核后进入任务包 |
| Runbook | 某个 Agent 自己的步骤链 |
| Workitem | 需求 / Bug / 任务载体，绑定流程与当前步骤 |
| Dispatch | 「某工单的某一步交给某 Agent 的某执行器」的一次记录 |
| Task Package | 运行前冻结的身份、技能、记忆、流程、队友产物快照 |
| Handoff | 当前执行者上报下一棒交给谁 |

这类平台常见的核心架构事实是：**平台只负责派发与调度，步骤怎么走、下一棒交给谁，由本地 Agent 按 runbook 自己决定并上报**。这让流程灵活，但也让平台无法强约束执行边界。

### 本项目的取舍

| 常见做法 | AutoSDD | 理由 |
|---|---|---|
| Agent（含版本） | `agents`（单版本） | 最小化；版本化留到路线图 |
| Skill / Memory 挂载 | `skills` / `knowledge_items` + 关联表 | 保留「可挂载」这一核心体验 |
| 每 Agent 一条 runbook | 任务级 `workflows` + `workflow_steps` | 用户要的是「一个任务由哪些 Agent 跑」，流程应属于任务/场景，而非某个 Agent |
| 线性 runbook + Agent 自上报 handoff | 显式 `depends_on` 就绪队列 | 平台强约束下一棒；线性是 DAG 的简单形态 |
| Workitem | `tasks` | 保留标题、描述、场景、状态 |
| Dispatch | `step_runs` | 一次「任务某步交给某 Agent」的完整记录 |
| Executor daemon / WebSocket | `AgentExecutor` 接口（Mock / Anthropic / OpenAI 兼容） | 进程内执行，去掉调度基础设施；远程沙箱另行设计 |
| Task Package | `workflow_snapshot` + 上下文组装 | 运行开始冻结流程、Agent、技能、知识 |
| 小队、多租户、OSS、IM | 不做 | 与最小闭环无关 |

**一句话：AutoSDD 在最小范围里同时演示「谁来做」和「按什么顺序、拿到什么上下文、做到什么算完成」。**

## 演示数据

1. **资产**：7 个 Agent（需求分析师、系统架构师、开发工程师、测试工程师、代码评审员、技术写作者、文档专家）、9 个 Skill、8 条知识；2 个内置模型（Mock 默认、Claude Sonnet 5）。
2. **流程**：
   - 新功能开发：需求分析 → 架构设计 → 编码实现（人工卡点）→ 质量验证 → 代码评审（人工卡点）；
   - Bug 修复：问题定位 → 修复实现 → 回归验证；
   - 代码评审：静态评审 → 评审结论；
   - 代码文档编写与评审：文档编写（文档专家，直接以任务中的代码为来源）→ 文档评审（系统架构师，逐项对照代码）。
3. **任务**：一个已完成的历史任务（含 5 步产物），两个待运行任务（Bug 修复、代码文档编写）。
4. **演示路径**：总览 → 查看历史任务产物 → 新建任务（自动推荐「新功能开发」）→ 运行 → 观察流式输出 → 审批通过 → 成功；回到总览看数字变化。
